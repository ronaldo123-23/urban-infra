# 인스타그램 가짜뉴스 판별기 — 개발 프롬프트

## 0. 이 문서를 읽는 AI에게

너는 이 웹 서비스를 만드는 개발자야. 아래 "1단계"만 구현하고, "나중에" 목록에 있는 기능은 만들지 마. 다만 나중 기능이 붙을 수 있도록 구조(폴더, 데이터 형식)는 미리 열어 둬. 모르는 부분이나 막히는 부분은 추측해서 채우지 말고 질문해.

## 1. 서비스 한 줄 설명

10대가 인스타그램에서 본 게시물 링크를 넣으면, 게시물 글을 읽어서 그 안의 주장이 사실로 확인됐는지 근거 기사 링크와 함께 알려주는 웹 서비스.

## 2. 문제 인식

10대는 인스타그램에서 자극적인 제목과 가짜뉴스를 걸러내지 않고 받아들이고, 그대로 공유해 퍼뜨린다. 이 서비스는 결론만 던져 주지 않고 근거를 함께 보여줘서, 확인하는 습관을 들이게 하는 것을 목표로 한다.

## 3. 대상 사용자

- 1차 타깃: 10대 (스마트폰 사용, 링크 복사·붙여넣기에 익숙함)
- 고령자는 나중에 별도 화면으로 다룬다

## 4. 플랫폼과 입력 방식

- 웹 서비스 (반응형, 모바일 우선)
- 입력 1: 메인 화면의 입력칸에 인스타그램 게시물 링크 붙여넣기 (iOS·안드로이드·PC 공통)
- 입력 2: 안드로이드에서는 PWA로 설치하면 인스타 공유 목록에 이 서비스가 뜨도록 manifest의 share_target 설정
  - iOS Safari는 Web Share Target을 지원하지 않으므로 iOS는 입력 1만 사용
- 지원 링크 형식: instagram.com/p/…, instagram.com/reel/… (릴스는 캡션만 읽고 영상·음성은 읽지 않음)

## 5. 기술 스택 (변경 가능, 바꾸려면 먼저 제안할 것)

- Next.js (App Router) + TypeScript
- 배포: Vercel
- 인스타 글 읽기는 반드시 서버(API Route)에서 처리 (브라우저에서 직접 요청하면 CORS로 막힘)
- 협업: GitHub 저장소 공유 (한 명은 Claude, 한 명은 아이패드에서 Codex 사용)

## 6. 1단계에서 만들 것 — "링크를 넣으면 글을 잘 읽는가"

### 6-1. 글 읽기 방법을 순서대로 시도

서버는 아래 방법을 위에서부터 시도하고, 성공한 방법과 실패 이유를 기록한다.

1. Meta 공식 oEmbed API (Meta 개발자 앱 등록과 oEmbed Read 권한 심사가 필요함. 심사 전이면 건너뛰고 기록만 남김)
2. 게시물 페이지의 메타 태그 (og:description, og:title 등)에서 캡션 추출
3. 둘 다 실패하면 사용자에게 "캡션을 복사해서 붙여넣어 주세요" 입력칸을 띄움 (수동 입력 대체 경로)

로그인 우회, 비공식 스크래핑 라이브러리, 계정 쿠키 사용은 금지.

### 6-2. 추출 결과 형식

```json
{
  "url": "원본 링크",
  "method": "oembed | meta_tag | manual",
  "author": "계정명 (얻을 수 없으면 null)",
  "caption_raw": "추출한 원문 전체",
  "caption_clean": "해시태그·이모지·멘션을 뺀 본문",
  "hashtags": ["..."],
  "fetched_at": "ISO 시간",
  "error": "실패 시 이유, 성공 시 null"
}
```

### 6-3. 화면

- 메인: 링크 입력칸 1개 + 확인 버튼
- 결과: 추출된 본문, 사용한 방법, 실패 시 수동 입력칸
- 1단계 결과 화면에는 판정을 넣지 않는다. 대신 "판정 기능 준비 중" 같은 빈 영역만 잡아 둔다

### 6-4. 1단계 완료 기준

- 공개 게시물 20개로 시험한다 (캡션 위주 게시물 10개, 카드뉴스 5개, 릴스 5개)
- 게시물마다 성공·실패 여부, 사용한 방법, 원문과 비교한 정확도를 표로 정리한다
- 캡션 위주 게시물 10개 중 8개 이상에서 캡션 전체가 빠짐없이 추출되면 1단계 통과
- 카드뉴스는 이미지 속 글자가 추출되지 않는 것이 정상이며, 실패로 기록만 한다

## 7. 나중에 (지금은 만들지 말 것, 구조만 고려)

> 2026-11-22 변경: 7-1~7-4(주장 추출, 검증 경로, 판정 4단계, 판정 결과 항목)는 2단계로 구현을 시작함. 7-5는 카드뉴스 이미지 OCR부터 지원한다.

### 7-1. 주장 추출

caption_clean에서 검증할 수 있는 주장만 문장 단위로 골라낸다. 의견, 감상, 광고 문구는 "판단 대상 아님"으로 분류한다.

### 7-2. 가짜뉴스 유형별 검증 경로

| 유형 | 검증 방법 |
|---|---|
| 통계 조작·뻥튀기 | 국가통계포털(KOSIS) 오픈API 수치와 대조 |
| 사실을 섞은 거짓 | 주장을 문장별로 쪼개서 각각 판정 (각 문장도 언론사 팩트체크 기사 검색으로 확인 — 2026-11-22 결정) |
| 완전한 거짓·조작 | 언론사 팩트체크 기사 검색 (네이버 검색 API 뉴스, "팩트체크 + 핵심어"로 검색) |

### 7-3. 판정 4단계

- 확인됨: 신뢰할 수 있는 근거 기사·통계가 주장과 일치 (2026-11-22: 원문에서 같은 대상·시점·조건의 수치나 명시적 문장을 찾았을 때만)
- 근거와 다름: 팩트체크 기사나 공식 통계·원문이 주장을 반박하거나 수치가 다름 (2026-11-22 "거짓으로 밝혀짐"에서 이름 변경)
- 아직 확인 안 됨: 관련 보도나 검증이 아직 없음 (최근 속보일 수 있음을 함께 안내)
- 판단 대상 아님: 의견, 감상, 광고

주의: "여러 언론사에 나왔다"만으로 확인됨 처리하지 않는다. 같은 보도자료를 받아쓴 기사는 1개로 센다.

### 7-4. 판정 결과에 반드시 들어갈 것

- 주장 문장
- 판정 단계
- 근거 기사·통계 링크 (최소 1개. 링크가 없으면 "확인됨"이나 "근거와 다름" 판정을 낼 수 없다)
- 왜 그렇게 판정했는지 한 줄 설명 (예: "기사에 인용된 통계는 2019년 수치임")

AI(LLM)로 판정할 경우, AI가 출처를 지어내지 않도록 실제 검색 결과로 받은 링크만 근거로 쓰게 한다.

### 7-5. 그 외

- 카드뉴스 OCR. 공개 게시물 미리보기의 대표 이미지 한 장을 자동으로 읽고, 나머지는 사용자가 스크린샷으로 첨부한다. 추출한 글과 숫자는 검증 전에 수정할 수 있다.
- 고령자용 화면 (큰 글씨, 단계 축소)
- 판정 기록 저장, 공유 기능

## 8. 참고 자료
